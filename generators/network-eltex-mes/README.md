# Eltex MES Switch Syslog

Generates ECS-compatible JSON for Eltex MES23xx, MES33xx, MES35xx, and MES5324 switch events. `event.original` and `message` carry the device's documented syslog **message body** (`COMPONENT-SEVERITY-MNEMONIC: text`). The surrounding syslog transport header is outside this generator's scope. This is an MES switch pack, not an Eltex ESR router pack.

There is no dedicated Elastic Eltex MES integration reference event to mirror. The [Eltex MES syslog message catalog](https://eltex.ru/storage/upload_center/files/46/MES23xx_MES33xx_MES35xx_MES5324_Log_reference.pdf) is the reference for native message names and parameters. The JSON adds ECS fields and `eltex.mes.*` parsed fields. All 15 documented identity and parameter fields used by the selected message formats are represented: component, severity code, mnemonic; connection type, user, source IP, destination IP, authentication method; interface, configured speed; MAC state, address, VLAN and port; and syslog server IP.

## Event Types

| Native message | Generated action | Routine frequency |
| --- | --- | ---: |
| `BRG_MACNTFY-I-MAC_CHANGED` | MAC learned / removed | 78% / 18% |
| `LINK-W-Down` / `LINK-W-Up` | Interface down / up | 2% combined; alternates state |
| `AAA-W-REJECT` | HTTPS login rejected | 0.5% |
| `AAA-I-CONNECT` then `AAA-I-DISCONNECT` | Normal admin session | 1.5% trigger, then a linked disconnect |
| `LINK-N-PortConfRecover`, `SYSLOG-N-CLEARLOGGINGFILE`, `SYSLOG-N-NOSYSLOGSERVER` | Anomaly sequence only | Once per 1,000 routine events when enabled |

Nine distinct native message names are generated by one reusable Jinja template.

The percentages are weights at the routine FSM state, not measured production rates. At the default one event per five seconds, the generator models a moderately active access switch. The abnormal sequence and linked normal disconnects add events to the output, so final percentages vary. MAC endpoints and VLANs are chosen from `samples/endpoints.json`; the single switch identity remains fixed across the stream.

## Anomaly Chain

With `anomaly_mode: true`, after 1,000 routine events the FSM emits these messages on the same switch in order:

1. Three `AAA-W-REJECT` events for `admin` over HTTPS from unusual source `10.99.4.21`.
2. `AAA-I-CONNECT` accepts that user and source.
3. `LINK-N-PortConfRecover` changes `te1/0/5` speed to `1G`.
4. `LINK-W-Down` reports that port down, then `BRG_MACNTFY-I-MAC_CHANGED` removes its MAC entry in VLAN 20.
5. `SYSLOG-N-CLEARLOGGINGFILE` clears the local logging file, followed by `SYSLOG-N-NOSYSLOGSERVER` deleting the configured syslog receiver.

Possible rules: repeated login rejection followed by success from the same source; a successful login from an unusual network followed by a port configuration change on the same switch; or port disruption followed by local log clearing and syslog receiver deletion. The native port and logging messages contain no administrator name, so a rule can establish temporal and device correlation, not prove which user made the changes. A collector may miss events after its own syslog destination is deleted; the deletion is deliberately last.

Set `anomaly_mode: false` under `event.template.params` for background traffic only. That mode never emits the unusual source, target port speed change, local log clearing, or syslog receiver deletion. Ordinary rejected logins and port-state changes remain in the background.

## Parameters

### Event Parameters

Edit `event.template.params` in `generator.yml`:

| Parameter | Default | Meaning |
| --- | --- | --- |
| `switch_name`, `switch_ip` | `mes-access-01`, `10.40.0.11` | One MES switch identity |
| `normal_user`, `normal_source_ip` | `netops`, `10.40.1.25` | Routine HTTPS administrator session |
| `unusual_user`, `unusual_source_ip` | `admin`, `10.99.4.21` | Anomaly login identity and source |
| `target_port`, `target_mac`, `target_vlan` | `te1/0/5`, `e0:d9:e3:2c:19:b0`, `20` | Linked port and MAC events |
| `syslog_server_ip` | `10.40.0.12` | Receiver removed at the end of the sequence |
| `anomaly_interval_events` | `1000` | Routine events between anomaly sequences; also bounds the counter |
| `anomaly_mode` | `true` | Enable or disable the complete anomaly sequence |

### Output Parameters

The shipped pack writes `output/events.json` under the generator directory. It declares no top-level `${params.*}` or `${secrets.*}` output overrides. Change `output.file.path` for a different local destination, or replace the output plugin configuration for a SIEM endpoint.

## Usage

From the content-packs repository root:

```bash
eventum generate --path generators/network-eltex-mes/generator.yml --id mes --live-mode true
```

Change the cron expression or count in `generator.yml` to adjust the rate.

## Reference and Limits

- [Eltex MES23xx/MES33xx/MES35xx/MES5324 syslog message catalog](https://eltex.ru/storage/upload_center/files/46/MES23xx_MES33xx_MES35xx_MES5324_Log_reference.pdf): `AAA-I-CONNECT`/`DISCONNECT`, `AAA-W-REJECT`, `LINK-W-Down`/`Up`, `LINK-N-PortConfRecover`, `BRG_MACNTFY-I-MAC_CHANGED`, and `SYSLOG-N-*` names and examples.
- [Eltex MES Series operation manual](https://api.eltex-co.com/storage/upload_center/files/35/MES_Series_user_manual_6.6.5%28en%29.pdf): logging host and AAA login logging configuration.
- [Elastic ECS reference](https://www.elastic.co/guide/en/ecs/current/ecs-field-reference.html): normalized field names.

The catalog shows `LINK-W-Up` in its example while labeling the message severity “Informational.” The generator preserves the example's `W` prefix and maps it to `log.level: warning`. It does not invent a syslog header, command audit record, ACL rule change, or a user field on configuration messages. Some native messages depend on device logging settings, such as AAA login logging.
