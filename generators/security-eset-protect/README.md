# ESET PROTECT On-Prem CEF events

Generates ECS-enriched CEF records for ESET PROTECT firewall, HIPS, and threat events. The CEF record is in `event.original`; endpoint UUID and host fields support cross-category correlation.

## Event types

| CEF category | Routine mix | ECS category | Meaning |
| --- | --- | --- | --- |
| `ESET Firewall Event` | About 45% | network | Port-scan detection blocked |
| `ESET Threat Event` | About 30% | malware | File threat cleaned |
| `ESET HIPS Event` | About 25% | intrusion_detection | Suspicious launch blocked |

One `any` template emits a CEF 0 header and documented category-specific extension keys. The mix is a synthetic test profile, not a measured ESET deployment rate.

## Anomaly Chain

`anomaly_mode` defaults to `true`. After 80 routine records, endpoint `ws-fin-07` logs three HIPS blocks for execution of `C:\Users\Public\invoice-viewer.exe`, then a threat event that deletes the same file. Correlate `deviceExternalId`/`host.id` and HIPS `cs5` with threat `filePath` within a short window. Repeated blocked execution before cleanup can point to a retrying launcher or malicious persistence. With `anomaly_mode: false`, only independent background firewall, HIPS, and threat records are emitted.

## Parameters

### Event Parameters

Edit `event.template.params` in `generator.yml`.

| Name | Default | Purpose |
| --- | --- | --- |
| `anomaly_mode` | `true` | Include the HIPS-to-threat chain |
| `anomaly_interval_events` | `80` | Ordinary records between chains |
| `protect_version` | `11.1.0.0` | CEF device version |
| `protect_host` | `protect-01.example.test` | Management server |
| `target_host` | `ws-fin-07` | Chain endpoint hostname |
| `target_ip` | `10.20.1.47` | Chain endpoint address |
| `target_device_id` | `82e114a8-9070-4868-8ee2-1e87b7b85ee3` | Chain endpoint UUID |
| `target_path` | `C:\Users\Public\invoice-viewer.exe` | Chain file path |
| `target_user` | `EXAMPLE\maria` | Chain account |

### Output Parameters

The shipped configuration writes `output/events.json` and requires no output overrides. To deliver to a SIEM, replace `output.file` and set top-level `${params.*}` endpoint values and `${secrets.*}` credentials as appropriate.

## Usage

```bash
eventum generate --path generators/security-eset-protect/generator.yml --id eset --live-mode false
eventum generate --path generators/security-eset-protect/generator.yml --id eset --live-mode true
```

## Compatibility and references

[ESET PROTECT On-Prem 11.1 CEF documentation](https://help.eset.com/protect_admin/11.1/en-US/events_exported_to_cef_format.html) defines header class IDs and the firewall, HIPS, and threat extension keys used here. CEF `filePath` uses a file URI; HIPS `cs5` uses a Windows path. The vendor page assigns firewall class IDs to 200–299 although its firewall sample shows `109`; this pack uses `209` from the documented category range. ESET exports these categories only when the relevant log-export settings and endpoint detections are present. The ECS envelope is generated by Eventum, not sent by ESET.

[KUMA 4.2 lists an ESET PROTECT 11.0 syslog CEF normalizer](https://support.kaspersky.ru/kuma/4.2/255782). This pack uses the vendor's 11.1 CEF field reference and emits a bare CEF record rather than a syslog envelope. Compatibility with that KUMA 11.0 normalizer has not been verified; use a matching CEF parser and transport wrapper. No Elastic ESET PROTECT CEF sample was used as a source reference.
